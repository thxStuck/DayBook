What it is

UAC (Unix-like Artifacts Collector) collects logs, configuration, command output and a file system timeline from a Linux system. DayBookEvtxMacOS parses an extracted UAC collection into a case and lets you work with it the way you work with Windows logs: DQL search, click-to-filter, timeline, logs, entities, sessions and processes.

Layout of a collection:

PathContents
uac.logUAC's own log: version, command line, OS, host, the system's time zone
[root]/…copies of the system's files under their original paths (/var/log, /etc, home folders…)
live_response/…command output at collection time (processes, network, packages, disks…)
bodyfile/bodyfile.txtfile system timeline (Sleuth Kit format)
hash_executables/, system/, chkrootkit/, ssh/hashes of executables, lists of suid / hidden / writable files and more

Import

  1. File → New Case from Logs… (⌘N) and choose the collection folder (or a folder with several collections). Extract a uac-*.tar.gz archive first.
  2. In the import options choose Linux — UAC collection. It is preselected when the folders hold a UAC collection and no .evtx files. The sheet lists the collections found: host, UAC version, OS, time zone and collection time.
  3. Options: file system timeline (bodyfile) — up to four events per file of the system (millions on large servers); SHA-256 of source files.

Source files are opened read-only. Symbolic links inside a collection are not followed: they point into the analysed system, not this Mac.

From the command line: evtxdump ingest case.daybook <collection folder> --linux (without the flag, Linux is chosen when the folder holds a UAC collection and no .evtx files).

Time

The case stores time in UTC and shows it in the chosen zone.

  • A line with an offset (2026-09-27T01:31:03+03:00) has an exact time.
  • A line without one (classic syslog, dpkg, nginx error) is read in **the system's time zone from uac.log**; the event is flagged zoneAssumed.
  • Classic syslog (Sep 27 01:31:03) has no year. It is inferred from the file's modification time (from the bodyfile, else from the copy): the last line belongs to the year of the modification, a "December → January" step starts the next year. Flag yearInferred.
  • A record without a time of its own (a line that could not be parsed; bash history before HISTTIMEFORMAT was set) gets the time of a neighbouring record (timeCarried) or the file's modification time (timeFromFile) and keeps its place in the file's order.

The Data quality presets in the sidebar list all such events.

Fields and Action

Field names are CamelCase and match Windows fields where the meaning is the same: TargetUserName, SubjectUserName (with the host name as domain, so root of two machines stays two accounts), IpAddress, WorkstationName, CommandLine, ProcessId. Raw auditd and journald fields keep their names (exe, auid, _SYSTEMD_UNIT). A field whose name DQL treats as an alias (host, user, time…) is stored capitalised or renamed (Host, UserName, TimeRaw).

Action is a normalised action, the same across sources:

Examples:

Action in (auth_failure, invalid_user) | group by IpAddress | sort count desc
Action = process_exec and CommandLine contains wget
Action = http_request and HttpStatus >= 500 | group by Uri
Action = file_time and FilePath startswith /etc/cron and MACB contains m

Linux user names are case-sensitive: Root tried by a scanner is not root.

Sections of a Linux case

  • Events and Timeline — as for Windows; a "Program" column instead of the Event ID.
  • Logs — the /var/log tree: a log opens whole with all its rotations, or one file at a time.
  • System — details from uac.log, live_response command output by group, UAC's lists, hashes and the collected configuration and autostart files (cron, systemd, sudoers, authorized_keys, profile, PAM, audit rules). Files are read from the collection folder on demand.
  • Hosts, Users, IP addresses — the entity registry.
  • Sessions — wtmp logins: login → logout on the same terminal or a reboot, as last reads them.
  • Processes — program launches from auditd. auditd writes only the PPID, so parent → child links are reconstructed heuristically and marked 🔗.
  • In the event details the Record tab shows the original lines (all lines of an audit event or an apt transaction), FIELD=value lines of a journal entry, the decoded wtmp record; Hex shows the bytes.

Limits

  • The collection must be extracted: .tar.gz and .zip archives are not opened.
  • Sigma detections for Linux are not bundled yet: the Detections section is hidden in Linux cases.
  • Binary logs (mysql-bin.*, faillog, tallylog) are only listed as sources.
  • The records of one audit event are merged when they follow each other; records of different events mixed together give several events with the same AuditId.
  • The time of lines without a zone or a year is reconstructed by the rules above and flagged — check it against events with an exact time.
