Коротко

EventID = 4624 and LogonType in (3, 10) and not TargetUserName endswith "$"
| group by TargetUserName, IpAddress
| sort count desc
| limit 50
  • Запрос пишется в строке над таблицей и выполняется по Return или ⌘↩. Кнопка «Стоп» прерывает долгий запрос; новый запрос отменяет предыдущий.
  • Запрос работает вместе с чипами фильтров и выбранным интервалом времени: сначала применяются они, затем запрос.
  • Крестик в строке очищает запрос, кнопка «Сбросить всё» (⌘K) — запрос, фильтры и интервал.
  • Последние 50 запросов хранятся в истории (кнопка с часами).
  • Кнопка «?» открывает краткую подсказку.

Условия

Условие — это поле оператор значение. Условия соединяются словами and, or, not и скобками.

  • Приоритет: not выше and, and выше or.
  • Два условия подряд без связки означают and: EventID = 4624 LogonType = 3 — то же, что EventID = 4624 and LogonType = 3.
  • Ключевые слова пишутся в любом регистре.

Значения и кавычки

  • Без кавычек можно писать значения без пробелов и без символов ( ) , | " ' = ! < > ~: 10.20.30.40, S-1-5-18, 0x17, ADMIN$, C:\Windows\x.exe, *\powershell.exe, 10.0.0.0/8.
  • Значения с пробелами берутся в двойные или одинарные кавычки.
  • Внутри кавычек экранируются только своя кавычка и \\. Любой другой \ остаётся как есть, поэтому пути Windows можно вставлять без изменений: Image = "C:\Windows\System32\cmd.exe".
  • Имя поля с пробелами или совпадающее с ключевым словом пишется в обратных кавычках: `Threat Name` contains Trojan.

Регистр

  • Имена полей — без учёта регистра: eventid, EventID и @EventID равнозначны. Если в кейсе есть поле с точно таким написанием, оно выигрывает у одноимённого псевдонима: User — поле Sysmon, user — псевдоним SID пользователя.
  • Значения сравниваются без учёта регистра. Исключение — оператор ==.

Операторы

!=Всё, что не =, включая события, где поля нет совсем
< <= > >=Сравнение чисел или времени

startswith, endswithНачало или конец значения

После имени поля not допустим только перед in, contains и exists. Для остальных случаев пишите not перед условием: not Image endswith "\explorer.exe".

Подстроки и маски

  • contains, startswith, endswith сравнивают буквально: *, ?, %, _ — обычные символы. Пустое значение ничего не находит.
  • like и = с */? — маска. Экранировать сами * и ? нельзя.
  • Все эти операторы — без учёта регистра.

Регулярные выражения

  • Движок ICU (NSRegularExpression), без учёта регистра.
  • Ищется вхождение в любом месте значения. Чтобы привязать к началу или концу, используйте ^ и $.
  • Выражение проверяется на каждом уникальном значении поля, параллельно.
  • На одно значение отводится 2 секунды процессорного времени. Значение, на котором выражение работает дольше, пропускается. Детекты сообщают об этом предупреждением у правила; строка запроса такого предупреждения пока не показывает.

Подсети

cidr принимает IPv4 и IPv6: адрес/префикс, без префикса — один адрес. Значения полей вида ::ffff:10.1.2.3, [192.168.1.1] и fe80::1%12 распознаются.

Числа

  • <, <=, >, >= и between работают только с числами: десятичными (можно с минусом) или шестнадцатеричными 0x…. Нечисловые значения в такие выборки не попадают.
  • = сравнивает текст: TicketEncryptionType = 0x17 найдёт 0x17, но не 23; LogonType = 03 не найдёт 3.

Время

Поле time (также timestamp, timecreated) — это TimeCreated события, а если его нет — время записи в журнал.

time >= "2026-09-30 10:00" and time < "2026-09-30 12:00"
time between "2026-09-30 10:00" and "2026-09-30 12:00:30.5"
time >= 2026-09-30T07:00Z
  • Формат: ГГГГ-ММ-ДД[ ЧЧ:ММ[:СС[.fffffff]]], между датой и временем — пробел или T. Одна дата означает 00:00, доли секунды — до 7 цифр.
  • Без суффикса время понимается в выбранном часовом поясе отображения. Суффикс Z — UTC, +03:00 или -05:00 — явное смещение (с двоеточием).
  • Значение с пробелом берётся в кавычки.
  • time = … означает «в пределах этой секунды».
  • between включает обе границы, порядок границ не важен.
  • Для поля time допустимы <, <=, >, >=, between, =, !=. in, группировка и exists по времени не поддерживаются.

Примечание

Если сменить часовой пояс, уже выполненный запрос не перезапускается: его время было понято в прежнем поясе. Выполните запрос заново.

Интервал удобнее задавать на гистограмме: выделите область протягиванием и нажмите «Фильтр по выделению». Интервал появится оранжевым чипом.

Поиск по всем полям

Строка в кавычках без имени поля ищет подстроку во всех полях события, включая системные:

"mimikatz"
"mimikatz" "sekurlsa"            — обе подстроки (неявный and)
EventID = 4104 | search "Invoke-WebRequest"

Это поиск подстроки без учёта регистра, а не поиск по словам. Слово без кавычек считается именем поля.

Сравнение двух полей

Правая часть в обратных кавычках — это другое поле:

Image endswith `OriginalFileName`
TargetUserName != `SubjectUserName`
  • Операторы: =, ==, !=, contains/~, startswith, endswith.
  • Берётся первое значение каждого поля, рассматриваются события, где есть оба поля (!= включает и события без одного из полей).
  • Сравниваются поля данных события (EventData/UserData), не системные поля.

Поля

Поля данных события

  • <Data Name="X"> даёт поле X; безымянный <Data> — поле Data (может повторяться).
  • Для UserData имя — путь ниже корневого элемента через точку, атрибут — путь.атрибут.
  • Если шаблон записи не найден, поля называются Value[0], Value[1], …
  • Неизвестное имя поля даёт ошибку с подсказкой похожих имён.

Уровень можно писать числом или словом в операторах =, !=, in: critical/критический = 1, error/ошибка = 2, warning/предупреждение = 3, information/info/сведения = 4 (включает и 0), verbose/подробно = 5.

Важно

Номер записи (EventRecordID), ProcessID и ThreadID хранятся в кейсе и показываются в деталях, но в запросах пока недоступны.

Конвейер

После условий через | идут стадии. | перед ключевым словом стадии можно не писать; запрос может начинаться сразу со стадии: | group by IpAddress.

СтадияЧто делает
where <условие>Добавляет условие через and. Можно повторять
search "строка"Добавляет поиск подстроки по всем полям
select f1, f2 (project)Задаёт колонки таблицы: время всегда первое, затем указанные поля, в конце — описание. Отбор событий не меняет
group by f1, f2Группы со счётчиками. По умолчанию — по убыванию числа событий. Событие без поля попадает в группу «—». Не больше 20 000 групп
sort f [asc\|desc] (order by)Сортировка. Учитывается первый ключ
limit n (take)Первые n строк или групп

Сортировка

  • sort time desc / sort time — новые сверху / старые сверху. Без sort time таблица сохраняет текущий порядок.
  • По другому полю: числа сравниваются как числа, текст — «естественно» (file2 < file10). Внутри равных значений — по времени; события без поля — в конце.
  • С group by: sort count — по возрастанию, sort count desc — по убыванию (по умолчанию), sort <поле группировки> — по значению.

Limit

  • Без сортировки limit n даёт n самых ранних событий; с sort time desc — n самых новых.
  • Гистограмма строится по результату до sort и limit.

Группы

Клик по группе показывает её события. Двойной клик или «Превратить в фильтры и показать события» превращает значения группы в чипы фильтров и убирает стадию group by.

Ошибки

Ошибка показывается под строкой запроса с позицией символа:

ЗапросСообщение
EventID = "4624Незакрытая кавычка (позиция 11)
(EventID = 1Ожидалась «)» (позиция 13)
EventID =Ожидалось значение
EventID = 4624 fooПосле «foo» ожидается оператор (=, !=, <, >, contains, in, …)
EventID = 1 \| limit xПосле limit ожидается число
Foo = 1Неизвестное поле «Foo» и подсказка похожих имён

Как выполняется запрос

  • При импорте каждая уникальная строка — значение или имя поля — один раз попадает в словарь. События получают номера в порядке времени. Для каждой пары «поле = значение» хранится отсортированный список номеров событий — posting-лист. Системные свойства хранятся так же, как поля @EventID, @Channel и т. д.
  • Запрос разбирается в дерево и никогда не превращается в SQL: ваш текст передаётся в фиксированные запросы к словарю только как параметр. Попытка SQL-инъекции в значении просто ничего не найдёт.
  • Каждое условие находит подходящие значения словаря: хеш для =, триграммный полнотекстовый индекс для подстрок, числовой индекс для < и >, перебор для регулярных выражений и подсетей. Затем объединяются их posting-листы.
  • and, or и not выполняются как пересечение, объединение и разность отсортированных множеств. Отрицание не материализует все события. Условия по времени — двоичный поиск по массиву меток времени.

Готовые запросы

Пресеты в боковой панели раздела «События». Их можно открыть, изменить и выполнить.
