Что такое кейс

Кейс — это папка <имя>.daybook, в которую приложение один раз разбирает журналы. Дальше вся работа идёт с кейсом: поиск, таймлайн, сущности, детекты.

Файл в папке кейсаЧто хранит
case.sqliteБаза кейса: события, словарь значений, индексы, сущности, закладки, результаты детектов. Рядом могут быть case.sqlite-wal и case.sqlite-shm
ts.binВремя каждого события (FILETIME, UTC) по 8 байт в порядке времени. По нему мгновенно ищутся границы временного окна
manifest.jsonСводка импорта: версия схемы, дата, выбранные источники, итоги (файлы, события, копии, восстановленные записи, ошибки, длительность)
  • Исходные журналы не копируются в кейс. В кейсе хранятся абсолютный путь к каждому файлу, его размер, SHA-256 (если включено) и статистика разбора.
  • Поля событий целиком лежат в кейсе. Из исходного файла по запросу читаются только XML и сырые байты записи (вкладки XML и Hex в деталях).
  • Папку кейса можно переносить. Если переместить исходные журналы, всё работает, кроме вкладок XML и Hex: там будет сказано, что исходный файл не найден, и показан путь, по которому он ожидался. Функции, чтобы указать новое место исходников, пока нет.

Открыть кейс: «Файл» → «Открыть кейс…» (⌘O) и выбрать папку .daybook. Недавние кейсы перечислены на стартовом экране. Закрыть: «Файл» → «Закрыть кейс» (⇧⌘W).

Создание кейса

  1. «Файл» → «Новый кейс из журналов…» (⌘N).
  2. Выберите одну или несколько папок с журналами и/или отдельные файлы .evtx — или распакованный сбор UAC с Linux-системы.
  3. Укажите, где сохранить кейс. По умолчанию — ~/Documents/DayBook/<имя источника>.daybook. Если кейс с таким именем уже есть, macOS спросит, заменить ли его.
  4. В параметрах импорта выберите систему: Windows — журналы .evtx или Linux — сбор UAC. Тип подставляется по содержимому папок; там же видно, сколько найдено файлов .evtx и какие сборы UAC. Про Linux — отдельная страница: Linux (сбор UAC).
  5. Проверьте параметры импорта и нажмите «Начать импорт».

Все параметры по умолчанию включены и запоминаются для следующих импортов.

Какие файлы попадают в кейс

  • Папки обходятся рекурсивно, скрытые файлы пропускаются.
  • Из папок берутся файлы *.evtx (расширение без учёта регистра) и файлы без расширения, которые начинаются с сигнатуры ElfFile\0.
  • Файлы, выбранные явно, берутся независимо от расширения — формат проверяется по сигнатуре.
  • Символические ссылки: выбранная ссылка разрешается; ссылки на файлы внутри папок учитываются; в ссылки на папки обход не заходит (защита от циклов).
  • Старый формат .evt (Windows XP/2003) распознаётся, но не поддерживается.
  • Файл, который не удалось открыть, попадает в список «Не удалось открыть» в «Сведениях о кейсе»; импорт остальных файлов продолжается.

Этапы импорта

  1. Поиск файлов журналов.
  2. SHA-256 исходных файлов.
  3. Разбор записей (параллельно по чанкам, попутно собираются шаблоны со всех файлов).
  4. Восстановление записей из slack.
  5. Сортировка по времени и объединение копий.
  6. Запись событий в базу кейса — единственный этап с процентами прогресса.
  7. Индекс полей.
  8. Индексы базы.
  9. Полнотекстовый индекс.
  10. Реестр хостов, пользователей и IP.

Во время импорта видны текущий этап, число записанных событий и прошедшее время. Кнопка «Отмена» останавливает импорт и удаляет недоделанную папку кейса. После импорта кейс открывается сам.

Как разбираются файлы

Приложение использует собственный парсер EVTX и не зависит от Windows API.

  • Все физические чанки. Число чанков берётся из размера файла, а не из счётчика в заголовке: у «живых» (dirty) журналов этот счётчик устаревает, и самые свежие события лежат в чанках за ним. Такие события помечаются флагом beyondHeader.
  • Неполный последний чанк (меньше 64 КиБ) не разбирается. Его размер виден в колонке «Хвост, байт» в «Сведениях о кейсе».
  • Контрольные суммы. У каждого чанка проверяются CRC32 заголовка и области записей. При несовпадении разбор продолжается, а записи чанка получают флаг.
  • Повреждённый участок внутри чанка пропускается до следующей корректной записи. Записи после разрыва получают флаг afterGap.
  • Ошибка разбора записи не отбрасывает её: сохраняется всё, что удалось прочитать, ставится флаг parseError, а в XML добавляется комментарий о месте обрыва.
  • Шаблоны BinXML берутся из того же чанка. Если шаблона там нет (так бывает у восстановленных записей), он ищется во всех файлах кейса — флаг foreignTemplate. Если не нашёлся нигде, значения показываются как Value[n] — флаг missingTemplate.

Восстановление записей из slack

Slack — свободная часть чанка после последней живой записи. Там часто остаются старые записи.

  • Просматривается область после freeSpaceOffset (в чанке без корректного заголовка — весь чанк начиная с 512-го байта) с шагом 8 байт.
  • Кандидат принимается, только если совпадают все признаки: метка записи 0x00002A2A, размер не меньше 28 байт и умещается в чанк, копия размера в конце записи совпадает, данные BinXML начинаются корректно, время записи — между 1990 и 2100 годами.
  • Восстановленные записи помечаются флагом carved, время в таблице у них оранжевое.
  • Если такая же запись есть среди живых, при включённом объединении остаётся живая, а восстановленная становится её копией.

Объединение копий

Копиями считаются записи, у которых совпадают все четыре признака:

  • время TimeCreated с точностью до 100 нс (если его нет — время записи);
  • компьютер и журнал (без учёта регистра);
  • номер записи RecordID;
  • EventID.

Событием становится живая запись, а не восстановленная. Дальше выигрывает файл, путь которого раньше по алфавиту, затем меньший номер чанка и смещение. Событие получает флаг hasCopies, а в деталях появляется раздел «Копии этой записи» со списком мест: файл, чанк, смещение.

Примечание

Фильтр по файлу и счётчики по файлам учитывают только основную копию события. Сколько копий из файла ушло в другие события, показывает колонка «Копий схлопнуто» в «Сведениях о кейсе».

Флаг (для flag = …)Что означает

Где видны флаги:

  • строка «Флаги» в деталях события;
  • цвет времени в таблице: красный — parseError, оранжевый — carved, stale и afterGap;
  • раздел «Флаги записей» в боковой панели раздела «События» — клик добавляет фильтр;
  • запросы flag = carved, flag = timeSkew и пресеты группы «Особенности журналов»;
  • колонка «Флаги записей» в «Сведениях о кейсе»;
  • колонка Flags в экспорте.

Сведения о кейсе

Кнопка ⓘ на панели инструментов. Наверху — сводка:

  • события, файлы, дата создания, версия схемы;
  • сколько записей восстановлено из slack (найдено и уникальных), сколько копий объединено, сколько ошибок разбора;
  • параметры импорта;
  • красным — файлы, которые не удалось открыть.
